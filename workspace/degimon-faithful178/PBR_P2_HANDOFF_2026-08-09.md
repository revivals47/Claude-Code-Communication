### 3.1 型

★数値や位置を、それが**測られた枠**から切り離して持ち運ぶ★。★同じ数値でも、どの枠で測ったかで別物になる★。

| 枠 | 取り違えの実例(本日) |
|---|---|
| ★address 枠★ | file offset ↔ VA ↔ entry 相対 / ★savestate prefix `0x1A62`★ / ★overlay の `Load Address`★ / ★`0x80147358`★ |
| ★containment 枠★ | 物理的隣接 ↔ 論理的帰属 / ★`0x08BA`★ / ★AI table を「32 entry」と読んだ件(bound は `sltiu 0x13` = 19)★ / ★打切り tsv★ |
| ★control-flow 枠★ | ★「call は次命令に戻る」という前提★ / ★`0x67` = `0x800913C0` = BIOS A0(14h) = **longjmp** ゆえ戻らない★ |

★`0x800913C0` は worker2 が独立確認★【観測 = worker2】: `addiu $t2,$zero,0xa0; jr $t2; addiu $t1,$zero,0x14` = ★A0(14h)★。

> ★**訂正(worker2)**★: 起草初版で私は ★「直後の `0x800913D0` が A0(15h) = setjmp。longjmp/setjmp 対が隣接」★ と書いた。★**これは誤り**★。
> ★`t1=0x15` という**観測**は正しいが、それに付けた**ラベル(setjmp)は私が根拠なく付けたもの**★。
> ★しかも「追加の裏付け」として提示した = **自分で作ったラベルから支持証拠を捏造した**★。
> ★これは本日の型そのもの(観測とラベルの分離)であり、PRESIDENT が marker① で踏んだのと同型★。

★正しい対(worker1 の指摘 → worker2 が buffer 一致で独立確認)★【観測 = worker2】:

| thunk | `t1` | caller 数 | `$a0`(buffer) |
|---|---|---|---|
| `0x800913B0` | ★`0x13` = A0(13h) = **setjmp**★ | 2 | ★`0x800F076C` が `0x80164068`★ |
| `0x800913C0` | ★`0x14` = A0(14h) = **longjmp**★ | ★36★ | ★sample 4 件すべて `0x80164068`★ |
| `0x800913D0` | `0x15` | 15 | ★共有 buffer なし = 無関係★ |

★∴ 対は `0x800913B0`(**直前**)であって `0x800913D0`(直後)ではない★。★接地は「隣接」ではなく **buffer `0x80164068` が両端で一致すること**★。
★setjmp 側の呼び出し形も型どおり★: `0x800F0764` = `$a0 = 0x80164068` → `jal 0x800913b0` → `move $s1, $v0`(戻り値を捕まえる)。
★副次★: ★A0(14h) の caller 36 件は、judge 規則の議論に出てくる「36 件」と一致する★。
