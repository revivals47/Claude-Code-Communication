# worker1 の器の欠陥 — 実例つき（2026-08-15）

母数 = 本日 worker1 が自分で見つけて報告した器の誤り **10 型**。
すべて **私自身の出力で実害が出た** もの。名前ではなく **逐語の実例** と **検出法** を残す。

次に同じ器（MIPS 静的解析 + script walker）を作る人が、**同じ穴を掘り直さない**ためのもの。

---

## 型 1: 窓の端で落とす（本日 **6 回** — 最多）

| # | 症状 | 逐語の実例 |
|---|---|---|
| 1-a | `jr` で打ち切り、**遅延 slot 1 語**を落とす | `0x800913C0`: `addiu $t2,0,0xA0` / `jr $t2` / **`addiu $t1,0,0x14`** ← これを見ず「戻る」と誤断 |
| 1-b | 窓 40 語固定で arm の端を落とす | 0x4A の longjmp は arm 先頭から **142 語**目（0x800ED76C） |
| 1-c | 関数の頭まで遡らない | `0x80105460` の gate 読みは **126 語手前**（0x8010534C）。40 語窓で「門なし」と誤断 |
| 1-d | 短い arm を実体と誤認 | 0x6B の arm は **2 語**で、実体は `beq → 0x800EF318` の先 |
| 1-e | `jr` を越えて次の関数に入る | 0x6B 走査で「前進 −2」を拾ったが、それは**隣の関数の pop 復元** |
| 1-f | 出口の探索を 184 語で打ち切る | `0x800EF4F0` は **longjmp で抜ける**ので `jr $ra` が無い（台帳 §4 が明示的に警告していた） |

**検出法**: 窓を 2 倍にして数が動くか。動いたら窓が原因。
**器側の処置**: **語数固定を使わない**。境界は構造で取る —
- 関数 = prologue（`addiu $sp,$sp,-N`）から次の prologue まで
- arm = 表の次の arm address まで
- 到達可能範囲 = **分岐/j を全部辿る不動点**（visited が増えなくなるまで）

⚠ ただし **「広げれば増える」は飽和の失敗とは限らない**（型 8 参照）。

## 型 2: inline の cursor 前進を数えない（**3 回**）

`jal` だけを数えて、関数が**自分で** `[gp-0x6CC8]` を進める形を見落とす。

```
0x800F5758  lw    $v0, -0x6cc8($gp)
0x800F5760  addiu $v0, $v0, 1      ← ★jal が 1 つも無い前進★
0x800F5764  sw    $v0, -0x6cc8($gp)
```

実害: `0x800F5750` を **+5** と出した（正 **+6**）。worker2 の独立読みで割れて判明。
同型: `0x800F1620`（jal 0 本で +2）、0x19 の項長を 3/5/7 と出した（正 4/6/8）。

**器側の処置**: **cursor cell への store を直接数える**。jal の一覧に頼らない。

## 型 3: 消費する callee を表に持っていない

`0x800F1660`（+4）が私の helper 表に無く、0x6C を **+4 対 TSV 8** の「食い違い」と誤報しかけた（報告前に自己発見）。

**器側の処置**: 未知の callee は **0 で埋めず「未確定」を返す**。合計に混ぜない。

---

## 型 4: operand の位置を逐語抜きに決める（**3 回**）

| 誤 | 正 | 逐語の根拠 |
|---|---|---|
| 0x4B の operand を u16 @p+2 | **byte 3 つ** | `4b 39 02 ff` を u16 で読むと 0xFF02 = 明らかに値でない |
| 0x16 の飛び先 u16 @p+1 | **@p+2** | `0x800F0E6C` = **1 byte skip** + 2（台帳 :162） |
| 0x1C の flag を u16 @p+1 | **@p+2** | 形は `1C 00 <flag> 00` |

**検出法**: 出た値が**意味のある範囲に入るか**。0x4B の飛び先は 74% が entry 長を超えていた。
**器側の処置**: fetch helper の**逐語**（何 byte skip して何 byte 読むか）を先に確定する。

---

## 型 5: 自分が発明した規則を code 由来と混同（**2 回**）

- 「**0xFF の後に 0 が続くときだけ止まる**」— **code に 1 行も無い**。band 6 入口 `0x800EC404` は 0xFE/0xFF を同じ分岐で `jal 0x800EF39C` に入れるだけ。この 1 個の発明が **停止 164 件のうち 142 件**を作っていた。
- 「0x19 の項長は g で決まる」— g の集合 `{0,8,0x10,0x18}` は **code 由来で正しかった**が、**終端と継続の規則**は別物だった。

**検出法**: **規則ごとに「出所は逐語か / 台帳か / 自分の前提か」を書く**。書けないものが発明。
**器側の処置**: 規則を code の address と対で持つ。address を書けない規則は使わない。

---

## 型 6: seen-set で再帰を切る（過少に出る）

helper の前進量を再帰集計する器が、**同じ helper の 2 回目以降を visited で切って**いた。
`0x800F0E6C` は `0x800F0EDC` を 3 回呼ぶが、1 回しか数えない。

**器側の処置**: 呼び出し**回数**を数える。再帰検出は**「0」ではなく「不明」を返す**。
（この「0 を返さない」が後で実害を止めた — 「上界 4」と書いたおかげで誤った 0 が混ざらなかった。）

---

## 型 7: 排他な枝を両方足す（過大に出る）

`0x800F5300` を store 直読器で測ると **+6**。実際は `0x800F5328 beq` の
枝A = 0x800F1078(+2)+0x800F1038(+2) = 4、枝B = 0x800F1078(+2)+0x800F1620(+2) = 4 で **+4**。

**検出法**: **fetch を跨ぐ分岐が在るか**を数える。在れば和は上界。
**器側の処置**: 全 path を辿って **min/max** を出す。min≠max なら「条件付き」と印字する。

---

## 型 8: 飽和と構造を取り違える

worker3 に「窓を広げて数が変わらないことを確認したか（飽和検定）」と問われ、やったら**飽和していなかった**（次の arm +100 語で 40 arm が動く）。

**ただしこの場合、飽和は正しい検定ではない** — 次の arm より先の byte は**別 opcode の code** で、増えたのは**発見ではなく汚染**（0x7B/0x7C/0x7D の消費が −2 = 隣の arm の pop 復元）。

**教訓**: 窓の正当化には **2 種類**ある。
- **飽和**（広げても増えない）— 到達可能範囲・共通 tail の展開に使う
- **構造**（境界の外は別のもの）— arm・関数の境界に使う

**どちらで正当化しているかを書く。** 私はそれを書いていなかった。

---

## 型 9: 「grep 済」と書いて出力を見ていない（**3 回**）

「当たり 0 件」と宣言した後に実際は 1 件 / 2 件 / 5 件ヒットしていた。
「grep 済」は **grep した事実**であって **中身を見た事実ではない**。

**器側の処置**: **grep の行を貼ってから書く**。件数を数字で書く（数えざるを得なくなる）。

---

## 型 10: 再現しない数を出した

同じ器・同じ母数で **1,660/30** と **1,299/28** の 2 つを出した。
摘みを 8 条件で全数掃引したところ **1,660/30 は 4 条件で再現、1,299/28 はどれでも出ない** ⇒ **1,299 を撤回**。

⚠ **「再現しないから落とす」は「残った方が正しい」の証明ではない。** 1,660 も 1 器のまま。

**器側の処置**: 数を出すたび **器の設定（摘みの値）を数と一緒に印字する**。

---

## まとめ — この器を作る人へ

1. **語数固定の窓を書かない。** 境界は prologue / 次の arm / 不動点で取る。
2. **cursor の store を直接数える。** jal の一覧を信じない。
3. **未知は 0 でなく「不明」。** 合計に混ぜない。
4. **operand の位置は fetch helper の逐語から。** 値の範囲で検算する。
5. **規則ごとに出所（逐語の address / 台帳 / 自分の前提）を書く。** 書けないものは発明。
6. **分岐を跨ぐ和は上界。** min/max を出す。
7. **窓の正当化が飽和か構造かを書く。**
8. **grep は行を貼ってから。**
9. **数と一緒に器の設定を印字する。**

いずれも「注意する」では防げなかった。**器が強制する形**にして初めて止まった。
