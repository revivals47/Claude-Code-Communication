# runtime 観測 manifest（初版 2026-08-11）

PRESIDENT #46 (216) の裁定で作成。

## なぜこの器が要るか

**user の観測回数は有限資源。** ∴ 1 回の観測で 1 つの問いにしか答えられない形で出さない。

ただし **「束ねる」は放置と紙一重**である。器を作った時点でのみ、束ねる決定が有効になる。

**発注は PRESIDENT が manifest 完成後に 1 便でまとめて行う。boss1 から user へは出さない。**

## 入れない基準

- **静的に読めるものは入れない。** 例: `s1 == 3` の経路（PRESIDENT #46 (216) D）は static で読めるので除外。
- 「あると嬉しい」は入れない。**その観測が無いと決まらない現行数値がある**ものだけ。

## 登録項目

| # | 項目名 | 観測対象（address / size / stride） | 必要な game state | これが決めること | 取れない場合に残る不確定 | 依存している現行数値 |
|---|---|---|---|---|---|---|
| **A** | VM 停止 flag の clear 条件 | `0x801640B8` + `0x14`、**1 byte × 6 slot、stride 0x34** | script 実行中（VM が走っている任意の場面） | band 外 opcode で VM が**止まるか再開するか**。`(byte & 0x0F) != 0 && (byte & 0x40) != 0` の slot が 1 つでもあれば再開 | band 外打切の採否が決まらない | worker1 **−16.42%**（40,855 → 34,146）/ worker2 の L・N' 系列。**命令数が 2 倍以上振れる** |
| **A2** | VM 停止 flag の set 条件（A と同時取得可） | `0x80145E48` + `0x12`、**halfword × 6 slot** | 同上 | 停止 flag を立てる 3 つ目の site（`0x800F2F88`）の発火条件 | A の解釈が片肺になる | A と同じ |
| **B** | data 領域へ実行が入るか | 画面（player に見える挙動）+ 可能なら PC trace | 通常プレイ（複数場面） | **原盤が data を命令として読み続ける経路を実際に通るか**。通るなら player に何が見えるか | remake の HONEST GAP が「未判断」のまま | 忠実度課題。被覆率の分母定義そのもの |
| **C** | load 失敗時の stale buffer parse | 画面 + `.map` load 失敗を誘発した状態 | load 失敗が起きる場面（再現手順 未確立） | 原盤が stale buffer を 6 section として parse する挙動の可視結果 | P-S1 / P-S2 が HONEST GAP のまま | 既存 HONEST GAP（再現の要否 未判断） |

## 未登録（3 者からの追加待ち）

- worker1 / worker2 / worker3 が各自の未決から、**static で読めないもの**だけを挙げる。
- 挙げる時は上記 6 列すべてを埋める。**(4)「これが決めること」が 1 行で書けないものは登録しない。**

## 束ね方の注意

A と A2 は**同じ場面で同時に取れる**（どちらも VM 実行中の RAM）。B は複数場面の目視。C は再現手順が未確立なので、**手順の確立自体が先**。

∴ 現時点で **1 回の観測で確実に取れるのは A + A2 のみ**。B・C は別便になる可能性が高い。
