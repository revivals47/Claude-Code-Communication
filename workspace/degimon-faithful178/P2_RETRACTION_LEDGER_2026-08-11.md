# 撤回台帳 (2026-08-11)

PRESIDENT #39 (177) の指示で作成。

## なぜ必要か

boss1 は状態欄に「再現不能 0」と書き続けていた。しかし worker3 が P7 の 99 点を
「再現しない」として撤回した同じ報告の中に「再現不能 0」が併記されていた。

**撤回した値は再現不能 count から消える。∴ 不変量を「撤回」で維持できてしまう。**

「再現不能 0」は *生き残った値だけを数えた 0* になりうる。それは 2026-08-10 に
22 → 0 にした時の 0 とは別物である。

**一般形（PRESIDENT 逐語）**:
> 不変量を維持する手が 2 つ（直す / 消す）ある時、どちらで維持したかを併記しない限り、
> その不変量は情報を持たない。

これは分母の話である。対象に何度も当ててきた規範を、自分の運用指標に当てていなかった。

## 状態欄の書き方（以後これに従う）

- 現行値の再現不能 = N 件
- 撤回 = M 件（うち「再現しないため」= K 件）

片方だけを書かない。

### 新しい型: **全体では 0/1 だが、部分集合では成り立つ**（worker3、2026-08-11）

「script の命令は偶数整列か」を EXE で確かめた結果、**`lh`/`lhu`（`0x800F1038` / `0x800F1620`）と `lbu` 2 回（`0x800F1078` → `0x800F0EDC` ×2）が両方実在**。
∴ **「すべての命令が偶数整列」は接地しない / 「u16 operand を `lh`/`lhu` で読む opcode の target」に限れば接地する**。

⇒ **2 択（整列する / しない）の外に「opcode ごとに違う」という第 3 の答えがあった** = **H4 の実例**。
∴ 奇数 filter は **「`lh`/`lhu` を使う opcode の target に限る」**という限定つきでのみ機構接地する（worker3 の限定案、boss1 採用）。

**#36 の付記（boss1）**: **worker3 の誤読を boss1 が検算せずに GO にした**。boss1 の失敗表 #4（受け取った規則を使う前に落としてみなかった）の再発で、
今回は**規則ではなく「次の直しどころ」という因果の主張**だった。**落としてみる対象に、因果の主張が入っていなかった。**

**#32 の付記（PRESIDENT #55 (268) 逐語）**: 「**撤回の粒度も測定対象**」。全部を撤回すると、生きている 2 点まで消える。

**0 件を道具の失敗と読まずに doc を疑った**ことで、規範を配った便自身の母数誤りが出た。

## +35.26% を雑音と呼ばない（PRESIDENT #41 (187)）

- 問い: **原盤は実際に data 領域へ実行が入るのか。入るなら player に何が見えるのか。**
