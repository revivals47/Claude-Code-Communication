# 撤回台帳 (2026-08-11)

PRESIDENT #39 (177) の指示で作成。

## なぜ必要か

boss1 は状態欄に「再現不能 0」と書き続けていた。しかし worker3 が P7 の 99 点を
「再現しない」として撤回した同じ報告の中に「再現不能 0」が併記されていた。

**撤回した値は再現不能 count から消える。∴ 不変量を「撤回」で維持できてしまう。**

「再現不能 0」は *生き残った値だけを数えた 0* になりうる。それは 2026-08-10 に
22 → 0 にした時の 0 とは別物である。

**一般形（PRESIDENT 逐語）**:
> 不変量を維持する手が 2 つ（直す / 消す）ある時、どちらで維持したかを併記しない限り、
> その不変量は情報を持たない。

これは分母の話である。対象に何度も当ててきた規範を、自分の運用指標に当てていなかった。

## 状態欄の書き方（以後これに従う）

- 現行値の再現不能 = N 件
- 撤回 = M 件（うち「再現しないため」= K 件）

片方だけを書かない。

## 第 3 の型: 根拠交代（PRESIDENT #41 (190) で追加）

「直す」「消す」に続く**第 3 の維持手段**。値は動かないので、**外から誰も気づかない**。最も見えにくい。

記録項目: 旧根拠 / 新根拠 / 交代理由 / **強度の増減**

| # | 値 | 旧根拠 | 新根拠 | 交代理由 | 強度 |
|---|---|---|---|---|---|
| R1 | 被覆率 **32.95%**（worker3） | parity（奇数起点 = desync） | SJIS 対率 13.1% / param `0x1b`（命令整列位置に 0/49）/ 4 entry の sha256 一致 | parity は独立標本 5 件で精度 1/5 に落ちた（台帳 #22） | **低下**。新根拠は **N=1**。一般規則ではなく、他 entry へ適用しない（worker3 自己限定） |

**根拠が N=1 なら、値が生き残っても強度は下がっている。** 値の不変は健全さの証拠にならない。

## +35.26% を雑音と呼ばない（PRESIDENT #41 (187)）

boss1 は worker1 の判断（band 外を全て Len=1 にする機構値を既定にしない）を追認する際、
理由をこう書いた:

> 忠実度の対象は「機械の挙動」ではなく「script の意味」。data を命令として数えた被覆は忠実ではなく雑音。

**前半は誤りである。** 本 project は原盤の忠実 remake であり、**機械の挙動は player が観測できる限り忠実度の対象そのもの**。
実例は既に記録にある——「原盤は load 失敗時に stale buffer を 6 section として parse する。remake は再現していない」を
**HONEST GAP（再現の要否 未判断）**として残しており、機械の挙動を忠実度の対象から外していない。

正しい切り分け:

> **被覆率という測定器**の目的が script の意味の被覆であって、機械の挙動の再現ではない。
> 機械の挙動が忠実度の対象でないのではなく、**この metric がそれを測っていない**だけ。

∴ **+35.26% は別名で保存する**: 「**data を命令として読み続ける経路が到達しうる量 = +35.26%**」。
これは remake の忠実度課題の入力であり、未決として立てる:

- 問い: **原盤は実際に data 領域へ実行が入るのか。入るなら player に何が見えるのか。**
- 決着: **runtime でしか決まらない。**

同型: worker1 の `0xFE`/`0xFF` 打切（機構では継続、慣習で打切、到達 2,690 件 = 6.58% = 慣習の最重量）。
**機構値と解析値の両方を残す。どちらかを雑音と呼んだ時点で片方が消える。**

## 読み方の注意

この台帳は「間違いの一覧」ではない。**撤回された値は、撤回されなかった値より検証されている。**
危険なのは台帳に載っている値ではなく、**一度も検定にかけられていない値**である。

現時点で最も重いのはそれで、worker2 が測った:

> 到達命令の **81.5%** (25,189 / 30,917) は **EXE と照合していない Len[]** の上に乗っている。

これは台帳のどの行より重い。
