# 撤回台帳 (2026-08-11)

PRESIDENT #39 (177) の指示で作成。

## なぜ必要か

boss1 は状態欄に「再現不能 0」と書き続けていた。しかし worker3 が P7 の 99 点を
「再現しない」として撤回した同じ報告の中に「再現不能 0」が併記されていた。

**撤回した値は再現不能 count から消える。∴ 不変量を「撤回」で維持できてしまう。**

「再現不能 0」は *生き残った値だけを数えた 0* になりうる。それは 2026-08-10 に
22 → 0 にした時の 0 とは別物である。

**一般形（PRESIDENT 逐語）**:
> 不変量を維持する手が 2 つ（直す / 消す）ある時、どちらで維持したかを併記しない限り、
> その不変量は情報を持たない。

これは分母の話である。対象に何度も当ててきた規範を、自分の運用指標に当てていなかった。

## 状態欄の書き方（以後これに従う）

- 現行値の再現不能 = N 件
- 撤回 = M 件（うち「再現しないため」= K 件）

片方だけを書かない。

## 読み方の注意

この台帳は「間違いの一覧」ではない。**撤回された値は、撤回されなかった値より検証されている。**
危険なのは台帳に載っている値ではなく、**一度も検定にかけられていない値**である。

現時点で最も重いのはそれで、worker2 が測った:

> 到達命令の **81.5%** (25,189 / 30,917) は **EXE と照合していない Len[]** の上に乗っている。

これは台帳のどの行より重い。
